# 代码检查与验收标准

本标准适用于 Reactive MP 的公共包、统一入口、原生开发宿主、文档站和开发工具，用于全量检查、专项检查、修复复查和交付验收。

L0—L7 表示审查视角及依赖次序，不要求代码按相同层数拆分。审查以原生小程序和已确定的库合同为基准，不能仅检查已有导出或测试加载的路径。

## 使用方式

1. 先明确合同、范围、源码／产物基线和本次允许执行的检查。
2. 全量检查覆盖所有适用层；专项检查选取相关条目并追查上下游。
3. 每项记录适用性、源码与调用链、方法、实际结果及证据。
4. 缺陷记录触发条件、影响和证据性质；修复后复查共同路径和相邻消费者。
5. 结论范围不超过实际检查和证据范围。

编号在本标准内保持稳定；新增条目使用新编号，不随排版重排。参考项目的同名编号不构成本仓库条目的替代依据。

| 层级 | 关注问题 |
| --- | --- |
| L0 基准与范围 | 应当支持什么，本次检查到哪里 |
| L1 接口与使用方式 | 原生和组合式代码能否自然接入 |
| L2 组织与复用 | 包、注册协议、上下文及资源由谁拥有 |
| L3 逻辑与类型 | 输入、阶段、事件和状态如何得到正确结果 |
| L4 时序、隔离与恢复 | 多实例、重入、异步与失败后是否仍正确 |
| L5 安全与信任 | 外部输入、路径、数据和工具边界是否成立 |
| L6 资源、性能与稳健性 | 规模增长和故障下是否保持可控 |
| L7 验证与交付 | 证据是否足以支持验收与发布 |

## L0：产品与检查基准

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| G01 | 保持原生小程序运行时增强定位。一次配置收集、多次实例运行是当前架构；不以砍掉动态声明、退回静态写法或引入模板编译来宣称完成简化。 | 当前合同、同一场景的静态／动态／混合用法及预期。 |
| G02 | 以原生平台能力和真实消费者盘点范围，包含未实现、未加载及未知兼容的能力。 | 包、导出、注册入口、原生能力、宿主、工具和明确排除项；关联能力 ID。 |
| G03 | 保留已有和并行修改，区分源码、锁文件、生成 vendor、文档产物与实际安装包；不重置工作区或清理用户资料制造干净基线。 | 版本或文件指纹、生成来源及并行影响。 |
| G04 | 按任务范围区分静态审阅、离线回归、类型、真实工具、实机、外部服务、压测和发布。文档修改不自动扩大执行范围。 | 目标、数据和环境、执行范围；外部操作有必要授权。 |
| G05 | 选择解决具体疑问的最小有效验证，已通过后不无故重复。性能压测仅在专用可控环境开展；可视化结果与逻辑证据分开。 | 检查目的、实际命令和结果、未执行项及理由。 |

## L1：接口设计与使用方式

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| I01 | 简化减少使用者必须理解的概念、决定和重复关系，不仅减少行数或支持项。普通 Hook 不因内部双阶段而要求业务到处判断阶段。 | 同业务、同输入结果的使用路径比较。 |
| I02 | 静态配置、动态声明和混合用法共享最终原生合同，最小用法可连续扩展为完整用法。文件级 JSON/WXML/WXSS 职责不被强行搬进 setup。 | 连续示例及其注册结果、实例行为对照。 |
| I03 | 注册定义、实例、页面角色、Store 与单次异步任务身份区分；取消、实例状态和清理不能固化进共享配置。 | 两个实例、共享 Store、组件页面及运行状态归属。 |
| I04 | 命名、参数方向、单位、路径语法、默认值和返回关系一致，保留 0、false、空字符串、null、undefined 的真实含义。 | 缺省、显式空值、覆盖及冲突用例。 |
| I05 | 保留原生参数、this、合法 getter、原型方法和同步／异步返回。需要返回值的回调不通过广播拼装结果；同步 setup 不假装等待 Promise。 | 原生回调、异步分享、thenable 和接收者用例。 |
| I06 | 只保留保护真实不变量的运行检查；明确入口能表达的身份不反复推导。允许按合同合并的声明不因预防误用而禁止。 | 每项断言的实际风险、合法边界和具体错误。 |
| I07 | index.d.ts、exports、真实实现和示例一致；原生类型不靠 any、宽泛 Record 或断言冒充完整支持，动态输入先保持 unknown。 | 正反类型用例、导出核对和实际值。 |
| I08 | 基础包独立可用，聚合入口转出同一实现；子入口及兼容入口不形成平行状态或执行路径。 | 独立消费者、实例身份和公开解析。 |

## L2：组织、职责与复用

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| A01 | shared 提供通用工具；reactivity 拥有追踪与作用域；store 拥有共享状态；runtime 拥有收集、实例及平台适配；统一入口只聚合。 | 实际导入与职责图；基础包不依赖 wx 或上层实现。 |
| A02 | 配置收集和实例执行共享声明协议，由各自阶段处理；进入、恢复和异常收尾由统一上下文边界拥有。 | register → collector → 原生注册 → instance → bind → dispose 调用链。 |
| A03 | 生命周期、事件、配置策略等稳定可枚举领域集中声明并驱动执行，不另维护漂移的检查清单和平行分发。 | 登记、分发、类型和文档的实际消费者。 |
| A04 | 拆分改善阅读与职责；相似入口复用公共实现并保留原生差异，不制造无职责转发链、复制变体或过度通用插件框架。 | 相似实现对照、共享处理器与特例依据。 |
| A05 | workspace 依赖和 exports 显式；不跨包相对读取私有实现，不借用别包 node_modules；公开导入不带入 Node 工具或无关平台副作用。 | 依赖声明、导入图和离线独立包消费。 |
| A06 | examples 是开发与验证宿主，消费当前源码；同步工具只处理交付和路径，不修改 setup、模板或业务语义。 | 源码到 vendor 的映射、变更传播和可复现准备命令。 |
| A07 | 原生模板、布局和事件保持原义；宿主展示预期、实际值、重置与重复操作，不用静态展示冒充核心验证。 | WXML/WXSS/JSON、事件绑定及可执行场景。 |

### 源码可读性

具体书写、职责划分和文件落位遵循[代码规范](code-standard.md)，本节规定检查与证据要求。

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| C01 | 人读的业务源码按统一格式工具与配置排版，不手写多语句单行堆叠；没有工具配置不能宣称已符合格式标准。 | 配置、适用范围及改动差异。 |
| C02 | 模块说明职责、所属层与关键导出；导出函数说明参数、返回、阶段行为、资源归属和异常，非显然逻辑解释原因。 | 文件头、JSDoc 与真实实现对照，不逐行复述代码。 |
| C03 | 类型字段和关键常量说明语义、约束及来源；目录按职责组织，避免平行目录或多类职责混放。 | 类型、常量、目录与消费者。 |
| C04 | 长期维护工具具有文件头和关键函数说明；测试、临时脚本不强制逐函数 JSDoc 或为整齐追加无信息注释。 | 范围与例外依据。 |

## L3：逻辑、类型与平台协议

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| B01 | 收集阶段允许正常求值，但不建立运行订阅或启动库管理的实例副作用；实例阶段建立独立状态。不得承诺隔离任意用户代码。 | 收集次数、实例次数、回调计数与重复注册对照。 |
| B02 | 静态与动态定义的覆盖／合并规则明确，未知合法原生字段不因白名单丢失；Behavior、definitionFilter 和混入定义后的入口仍有效。 | 注册配置快照与原生平台对照，不只比较对象字段存在。 |
| B03 | props 类型、默认值、工厂、comparer、observer、联合类型及真实实例值按适用框架处理，收集值不冒充最终实例值。 | schema、父级更新、非法值及相应框架场景。 |
| B04 | data、Signal、ref、carrier 和 setData 逻辑数据时序一致，路径与数组修改不漏通知；视图回调保持原生渲染完成语义。 | 修改后立即读取、回调内读取、深层同引用及数组用例。 |
| B05 | 生命周期、pageLifetimes、页面角色、返回值回调、事件参数与 this 保留原生合同；beforeDetach 和 detached 的职责不混同。 | Hook／原生同存、父子顺序、组件页面及返回值用例。 |
| B06 | 响应式动态依赖、computed、watch 旧值、批处理、暂停／恢复／once、深层增删替换及只读语义成立。 | 分支切换、连续写入、相同值和循环依赖正反例。 |
| B07 | 错误、同步返回、Promise、空值与未处理分别表达，不吞错、静默截断或假装成功；循环和递归有可解释的终止行为。 | 异常、thenable、无进展和错误传播用例。 |
| B08 | relations、组件导出、祖先定位、事件通道和第三方组件保留原生身份；导出对象不被误当原始实例。 | 多节点、target+回调、自定义导出与组件查询场景。 |

## L4：时序、多实例与恢复

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| D01 | 注册和 setup 可嵌套／重入，正常返回和抛错都恢复原来的上下文，不污染其他定义或实例。 | 内外注册、失败后再注册及两个实例交错。 |
| D02 | 实例状态不共享；Store 共享范围明确，配置收集不提前初始化真正单例；页面销毁不误停共享 Store。 | 收集后首次实例化、双页面、销毁及重建。 |
| D03 | 微任务、原生回调、定时器与异步结果有时序合同；销毁后待执行任务不回写失效实例，取消等待不冒充任务终止。 | 待刷新时销毁、迟到回调、取消、重复清理。 |
| D04 | 清理幂等，一项失败不阻止其余资源释放；业务异常与清理异常可定位。 | 多清理函数、抛错、重复 stop 和失败恢复。 |
| D05 | 分包、独立分包和多个运行时副本的隔离边界明确；进程内 Map 和 Store 不冒充跨包或跨上下文全局状态。 | 实际包图与各装载环境场景。 |
| D06 | 宿主 watch 同步、文档生成和打包消费不读取半成品或旧文件；受并行生成影响的结果不能沿用。 | 生成来源、删除文件后准备、并行影响及必要重验。 |

## L5：安全与信任边界

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| S01 | 外部属性、事件、路由参数和数据路径按真实边界处理；对象合并防止原型属性污染，序列化不泄漏实例内部、函数或敏感信息。 | 畸形路径、特殊键、不可序列化值及数据来源追踪。 |
| S02 | 工具使用参数数组、受限路径和明确生成目录；清理只作用于工具拥有的产物，不删除用户修改或跟随符号链接越界。 | 路径、符号链接、目标身份与删除范围。 |
| S03 | 小程序前端不承担服务端授权保证；示例不放 AppSecret、令牌或用户资料，日志和错误不回显秘密值。 | 客户端／服务端职责、合成秘密和输出核对。 |
| S04 | 本地预览与自动化服务有明确主机、端口和宿主身份；远端请求、审计数据发送、发布和凭据操作遵守实际授权。 | 网络入口、宿主校验、执行回执和授权范围。 |
| S05 | 核对锁文件、嵌套版本、安装脚本和实际依赖闭包；区分开发工具告警、发布运行依赖、公告命中与可达漏洞。 | 锁、包体、实际解析及可达性依据；未获许可不发送依赖树绕过限制。 |
| S06 | Markdown、HTML、源码引用和文档输出按相应上下文编码；不能因资料来自仓库而忽略生成器的路径与渲染边界。 | 输入到渲染和文件输出的路径、转义及负例。 |

## L6：资源、性能与稳健性

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| R01 | 订阅、父子作用域、祖先绑定、定时器、原生 on/off、observer 和任务有明确所有者及释放点。WeakMap/WeakRef 不替代主动解绑。 | 多轮创建销毁后的活动计数、失效订阅和资源趋势。 |
| R02 | 状态传播不造成循环、重复派生、无关实例更新或无界排队；优化不破坏同步读取、旧值及原生回调语义。 | 计算／通知次数、队列大小、结果等价与异常用例。 |
| R03 | 检查 setData 次数、路径数、字节量、序列化和复制成本；纯数据与无需上屏的状态不无谓全量提交。 | 数据规模阶梯下的提交量、操作次数和相同结果。 |
| R04 | 冷启动、配置收集、实例化、挂载及首次可用分阶段测量；单次收集不被误判为每次渲染成本，双阶段也不能成为无界重复工作的理由。 | 同设备、数据、日志与环境下的阶段和工作量。 |
| R05 | 入口、分包及独立宿主不重复交付无关依赖；高频事件、长列表、反复导航与大对象按真实消费者验证。 | 包图、包体、实例与提交规模、适用设备结果。 |
| R06 | 日志、截图和可选诊断失败不改写业务结果或重执行业务；超时、取消和失败能结束实际工作并继续处理后续任务。 | 截图失败、无响应工具、取消和资源回收。 |
| R07 | 性能结论有同条件、足够样本和阈值来源；功能正确、工作量减少、开发者工具表现及实机性能分别举证。 | 基线、原始指标、采样条件及结论范围；不以 Node 耗时冒充设备帧率。 |

## L7：验证、发布与交付

| 编号 | 检查与通过条件 | 最低证据 |
| --- | --- | --- |
| V01 | 验证行为和原因，不只断言实现形式；覆盖范围包含未加载逻辑，不能以导出数量或单项回归代替原生能力覆盖。 | 能力 ID → 源码 → 用例 → 平台场景映射。 |
| V02 | 分清源码审阅、消费者类型、Node mock、vendor 产物、独立 tarball、开发者工具、真实 AppID 与实机。 | 环境、版本、mock 边界、实际对象及未验证项。 |
| V03 | examples 使用当前工作区实现，验证器核对目标宿主；截图、预期值和工具启动成功均不单独证明行为正确。 | 包来源、宿主身份、真实数据与交互结果。 |
| V04 | 包导出、类型、依赖、发布白名单及 README 在实际 tarball 中有效，独立消费者不借用 workspace 私有文件。 | 打包清单、隔离安装、真实解析和消费结果。 |
| V05 | 修复后复查共享处理路径、其他消费者及相邻边界；放宽预防性检查仍须证明核心不变量成立。 | 原触发条件闭合、合法路径及必要负例。 |
| V06 | 文档、类型、宿主、生成来源与公开行为同步；正式参考和计划／过程记录分开，生成产物从来源更新。 | 按[文档规范](documentation-standard.md)核对内容、引用与生成差异。 |
| V07 | 公开包首次安装、原生接线、运行、结果读取和元数据准确；发布单独授权，成功后核对公共 registry 的实际可用性。 | 包体及发布记录；未发布不宣称公开可安装。 |

不能通过删除必要校验、把错误行为改为期望、mock 掉被测规则、排除未加载模块或缩小统计分母制造通过结果。专项检查不凭空设统一覆盖率门槛；任务要求全分支时，未覆盖分支须继续验证、证明不可达或说明合理排除依据。

## 验收状态

| 状态 | 使用条件 |
| --- | --- |
| 通过 | 该条目合同明确，必要证据充分，结果符合要求 |
| 不通过 | 已复现缺陷或源码确认的可达违约路径，说明条件与影响 |
| 未验证 | 证据、环境或执行范围不足；注明缺少哪一层 |
| 不适用 | 对象没有该能力或风险面，并有依据，不用于隐藏未检查项 |

发现项另标记：已复现、源码确认、依赖公告命中、条件性推导。严重程度结合可达性、平台条件、数据影响及恢复成本判断。选中条目仍有未关闭缺陷或缺少要求的验证时，整体不得写成验收通过。

| 可读性与组织 | A01—A07、C01—C04；职责、公共实现和实际消费者 |
| 文档与示例 | A06—A07、V03、V06—V07；单一来源、首次使用和导航 |

## 可复用检查入口

| 入口 | 证据范围 |
| --- | --- |
| [响应式回归](../tests/reactivity.test.mjs) | 状态、依赖、作用域与 Store 的选定用例 |
| [运行时回归](../tests/runtime.test.mjs) | Node 模拟入口下的配置与实例行为，不代表全部真实平台语义 |
| [工作区回归](../tests/workspace.test.mjs) | 依赖边界和准备后模块消费 |
| [消费者类型用例](../tests/types/consumer.ts) | 选定合法／非法类型用法 |
| [打包验证](../scripts/verify-packages.mjs) | 实际 tarball 与独立离线消费者 |
| [微信验证器](../scripts/verify-wechat.mjs) | 对应宿主和工具环境下实际执行的场景 |
| [文档检查](../scripts/check-docs.mjs) | 导航、链接、源码引用和 API 生成一致性，不代替语义审校 |

`npm run check` 是聚合入口，并非每项小改都必须运行。按未决疑问选检查；纯文档任务通常只需要相关文档检查，改变站点生成时再构建。未执行的检查不能继承旧结果标为本次通过。
