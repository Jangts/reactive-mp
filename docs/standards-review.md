检查日期：2026-11-12；审阅起点为提交 afe3e05，结果对应当前工作区。对象为五个公共包、三个原生宿主、工作区工具、文档站、类型、README、指南与维护资料。依据为[代码规范](code-standard.md)、[文档规范](documentation-standard.md)和[代码检查与验收标准](code-review-standard.md)。本记录说明检查与修复，不代替正式使用合同。

## 范围与方法

按 L0—L7 逐层审阅，结合 W/O/F 编号归类；检查当前实现的可达路径，不以导出数量代表平台覆盖。保留同一 setup 的收集与实例运行、静态/动态/混合声明及原生文件组织。没有通过删除动态能力降低验收范围。

生产模块清单由 `scripts/check-code.mjs` 从 packages、scripts、apps/docs、examples 的实际文件生成；本次纳入 83 个 JS/MJS 模块，不包含 vendor、dist 和测试。检查器验证解析、模块说明和控制流代码块；人工审阅负责职责、调用链、合同和边界。类型另由消费者编译和实际 exports 对照检查。生成文件修改来源；测试仅对新增或修复的行为增加断言。

## 验证层次

- 本地自动化：37 项 Node 回归、消费者 TypeScript 编译、生产模块解析/格式、API 声明一致性、链接与源码引用检查。
- 交付验证：三个宿主从当前源码生成 vendor；五包实际打包，在工作区外独立离线安装、消费，并运行包内原生准备工具。没有发布到 registry。
- 文档验证：导航驱动的 16 页静态站及自包含源码页面构建；页面内容的正式合同与计划归属另行审阅。
- 测试不模拟平台权限、渲染后端、Behavior 平台合并顺序或真实设备性能。详细运行记录见[验证记录](verification.md)。

复现入口为 `npm run check`，实际链路包含格式、模块、回归、类型、宿主准备、文档与独立包检查。`artifacts/code-inventory.json` 保存模块清单；tarball 与消费回执由包检查生成，均为忽略提交的产物。
